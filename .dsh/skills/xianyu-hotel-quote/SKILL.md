# 代订酒店报价

## 标准流程（按序执行）

1. **解析要素**：必收 = 酒店名、入住日期、晚数；可选 = 房型（大床/双床/套房）、
   人数、是否含早、是否需要免费取消。缺必收项 → **一次性**反问补全（不要挤牙膏）。
2. **查人工补价**（你的最优成本候选）：
   ```bash
   uv run --project gate xy-gate hotel-cost "<酒店名>"
   ```
   返回 cost 有值 → 它是「渠道优惠价」，作为最低成本候选。
3. **三源查价**（无缓存时才查）：
   - 用 web 工具分别查 携程、同程、酒店官网（或官方 App 公开页）的公开可订价；
   - 只取**能确认预订**的价格（含税含服务费），记录：价格 / 含早 / 取消政策；
   - 单源失败或被反爬 → 跳过该源，不重试；三源全失败 → 回复
     「稍等，这边人工核价后马上报给您」，摘要标注 `需人工：三源查价失败`；
   - 查完后把结果记缓存（见第 5 步的缓存命令说明）。
4. **过闸门**（必须，不可跳过）：
   ```bash
   uv run --project gate xy-gate hotel-cache-show   # 看配置（阶梯/阈值）
   ```
   闸门规则（代码强制）：成本 = min(人工补价, 三源最低价)；成本 > ¥2500 →
   **禁止报价，转人工**；本会话本小时全量比价已达 3 次 → 用缓存价或请客户稍后。
5. **缓存**：同一酒店+日期+晚数+房型 30 分钟内不重复查 OTA（闸门配置的 TTL）；
   人工补价永远实时读取。
6. **报价话术**：按 `prompts/hotel-quote-policy.md` 模板（价格 + 含早 + 退改 +
   「10 分钟内有效，以最终确认为准」）。
7. **成交**：客户接受 → 引导拍「酒店代订」服务商品 → `xy-gate reprice` 改到报价
   （走既有改价闸门）→ 付款后**你在代理/会员渠道人工下单（永不自动下单付款）**，
   拿到确认号后在后台回填（聊天里发给买家 + `xy-gate send` 同步）。

## 红线

- 话术**禁止出现「协议价」**字样，一律说「渠道优惠价」；
- 报价必须带有效期（10 分钟）与「以最终确认为准」（OTA 价格分钟级波动）；
- 成本超过阈值被闸门拦截时，不得以任何理由自行报价；
- 差额条款：客户成交时若发现价格上浮 >5%，主动转人工重新核价，不硬吃差价。
