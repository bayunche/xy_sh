# 确认交易决策规则（confirm-decision）

供大脑核对与人工兜底场景使用。**注意：真正的闸门在 daemon 代码里
（gate/xy_gate/risk.py），本文只是把同样的规则讲清楚。两者冲突时以代码为准。**

## 前置事实核对（大脑职责）

1. 订单号必须来自卡片载荷或订单接口，禁止买家口头提供就信；
2. 金额必须来自订单详情（actualPayFee/payFee），禁止买家自报；
3. 买家 ID 与商品 ID 与订单详情一致才继续。

## 闸门规则（代码强制，按序）

| # | 规则 | 默认 |
|---|---|---|
| 1 | `auto_confirm.enabled` 总开关 | false（关闭时一律人工） |
| 2 | 商品黑名单命中 → 拒 | 空 |
| 3 | 商品白名单非空且未命中 → 拒 | 空（不限） |
| 4 | 买家黑名单命中 → 拒 | 空 |
| 5 | 金额 > `max_amount_cny` → 拒 | ¥100 |
| 6 | 该订单已有确认记录（冷却窗内幂等）→ 拒 | 3 分钟 |
| 7 | 全局 mode=dry-run → 模拟确认（记台账） | dry-run |

## 大脑补充判断（闸门之上的软规则）

- 订单标题与发货内容表明显不匹配（买家拍错 SKU）→ 不确认，提示人工核对；
- 买家刚刚在聊天里说「拍错了/不要了」→ 不确认，转人工；
- 金额未知（详情拿不到）→ 走 confirm-check 看 action，block 则转人工，
  allow 也建议人工复核（摘要里明确写"金额未经核实"）。

## 结果口径

- `allow`（live）：真调 API，报「已确认」；
- `dryrun`：报「**模拟**确认成功」，绝不表述成已发货；
- `block`：原样转述 reasons，报「需人工」。
